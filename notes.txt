# Reflection (needs the API key)
curl -s localhost:8000/api/verses/search -H 'Content-Type: application/json' \
  -d '{"mainPrompt":"i feel lonely but i still have hope"}' | python -m json.tool

# Explainability (no key needed — pure retrieval + LIME)
curl -s localhost:8000/api/verses/explain -H 'Content-Type: application/json' \
  -d '{"mainPrompt":"i feel lonely but i still have hope"}' | python -m json.tool




| Mode | What it does | Speed |
| --- | --- | --- |
| One-shot | A single search — the original pipeline | ~0.4s |
| Agent | A hand-rolled loop, searching as many times as it needs | ~15s |
| Agent (LangGraph) | The same thing built in LangGraph | ~15s |

Both agent modes add a **How it searched** panel showing every search they ran
and what came back. One-shot made no decisions, so it has no panel.

## Tests

```bash
cd backend
pytest -q                 # fast: no model, no network (~0.3s)
pytest -q -m slow         # loads the model, real retrieval (~20s)
pytest -q -m ""           # everything
```

Tests marked `live` make real API calls and are skipped by default.

## Notes

`requirements-dev.txt` adds pytest and `lime`, which powers the
`/api/verses/explain` endpoint. The Docker image installs plain
`requirements.txt` instead — lime pulls in scikit-image and matplotlib for about
150 MB — so **the deployed build has no `/explain` route**. That's deliberate:
`app/main.py` registers it only when lime is importable.

The image also installs the CPU-only build of torch from PyTorch's own index,
187 MB against 2.8 GB for the default CUDA wheel. There's no GPU in the
container, so none of the CUDA runtime would ever be opened.
